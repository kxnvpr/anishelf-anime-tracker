# AniShelf

Особиста бібліотека для пошуку аніме й манґи та відстеження перегляду/читання. Дані каталогу отримуються з [Kitsu API](https://hummingbird-me.github.io/api-docs/), а записи на полиці зберігаються локально у SQLite і доступні навіть без зовнішнього API.

## Запуск

Потрібен Python 3.10 або новіший. Усі залежності встановлюються в окреме середовище `.venv`, щоб не змінювати системний Python.

```powershell
# Якщо команда py доступна:
py -m venv .venv

# Або створи середовище тим самим Python, яким користуєшся:
& 'C:\Users\PC\.local\bin\python3.15.exe' -m venv .venv

# Встановлення та запуск через Python із .venv:
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe app.py
```

Відкрий `http://127.0.0.1:5000`. База `tracker.db` створюється автоматично поруч із `database.py`. За потреби інше розташування можна задати через змінну `TRACKER_DB_PATH`.

## Що вміє застосунок

- Головна `/` — окрема лендінг-сторінка з актуальним сезоном, трендами Kitsu, популярним/власним списком активності, статистикою та закликом до пошуку. Сторінка `/catalog` призначена для пошуку, підказок і додавання з каталогу.
- Шукати аніме або манґу в Kitsu та показувати назву, обкладинку, оцінку, кількість серій/розділів, категорії й опис.
- Показувати популярні тайтли на першому екрані; підказки в пошуку надходять із Kitsu після введення трьох символів.
- Додавати тайтли до особистої полиці зі статусом і поточним прогресом; у результатах пошуку статус можна вибрати прямо на постері.
- Шукати та фільтрувати локальну бібліотеку SQL-запитом за назвою, типом і статусом; сортувати за датою, назвою або оцінкою.
- Редагувати статус, прогрес, загальну кількість серій/розділів і власну нотатку; видаляти записи.
- Переглядати профільні лічильники: час перегляду орієнтовно рахується як 24 хвилини на відмічену серію; рівень залежить від кількості тайтлів і прогресу.
- Використовувати REST API для читання та зміни локальних записів.

Kitsu API: `GET https://kitsu.io/api/edge/anime?filter%5Btext%5D=Frieren&page%5Blimit%5D=12` або такий самий шлях `/manga`. API використовує JSON:API та не потребує ключа для публічного читання. Якщо каталог недоступний чи обмежив частоту запитів, застосунок показує зрозуміле повідомлення; локальна бібліотека продовжує працювати.

## Схема SQLite

Таблиця `tracks` — один запис на тайтл. `id` є локальним первинним ключем. Пара `(media_type, external_id)` унікальна та посилається на ідентифікатор запису Kitsu.

| Поле | Тип | Призначення |
|---|---|---|
| `id` | INTEGER PRIMARY KEY | Локальний ключ |
| `media_type` | TEXT | `anime` або `manga` |
| `external_id` | INTEGER | Ідентифікатор MAL із зовнішнього API |
| `title` | TEXT | Назва тайтлу |
| `image_url`, `synopsis` | TEXT | Обкладинка та опис |
| `score` | REAL | Оцінка MAL (0–10), якщо відома |
| `total_units` | INTEGER | Загальна кількість серій або розділів, якщо відома |
| `status` | TEXT | watching, reading, plan, completed, paused або dropped |
| `progress` | INTEGER | Переглянуті серії або прочитані розділи |
| `notes` | TEXT | Особиста нотатка |
| `created_at`, `updated_at` | TEXT | Час створення та останньої зміни |

Обмеження `CHECK` захищають статус, тип і прогрес; унікальне обмеження не дає двічі зберегти той самий тайтл. Пошукові значення передаються SQL через `?` placeholders.

## REST API

API працює лише з локальною базою та завжди повертає JSON.

| Метод і шлях | Дія |
|---|---|
| `GET /api/tracks?q=frieren&type=anime&status=plan` | Список із SQL-фільтрами |
| `GET /api/tracks/<id>` | Один запис |
| `POST /api/tracks` | Створити запис, відповідь `201` |
| `PATCH /api/tracks/<id>` | Змінити `status`, `progress`, `total_units` або `notes` |
| `DELETE /api/tracks/<id>` | Видалити запис |

Приклад `POST /api/tracks`:

```json
{
  "media_type": "anime",
  "external_id": 52991,
  "title": "Sousou no Frieren",
  "score": 9.3,
  "total_units": 28,
  "status": "watching",
  "progress": 4
}
```
